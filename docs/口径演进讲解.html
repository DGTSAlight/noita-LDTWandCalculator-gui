A

核心结论

一句话

现行口径把「抽几次」换成「走多久」，再用三范数聚合轮数。九个真实配方上，口径值与仿真时间的比值落在 0.93~1.31，中位 1.01。

三个指标同时改善：

指标 v7 经验系数 现行
比值中位 2.98 1.01

Spearman 秩相关 0.37 0.74

排序相关只有 0.74，原因是九个配方里有六个互相差距不超过 10%。详见面板 H。

B

五代口径

  1. v0.1.0等级求和各等级条件概率直接相加。跨等级不能相加，秩相关掉到 0.33
  2. v0.1.9归一化 + 三范数聚合方式从求和换成三范数，秩相关升到 0.995
  3. v0.3.4速率求和去掉归一化分母。调参会出现难度反涨，此版修好
  4. v0.3.7分组 v3拆成三个搜索模式，配经验倍率 E_G
  5. v0.4.0时间代价模型单位换成时间，删掉 E_G。现行

前三代的单位是「抽取次数」，第四代仍是，第五代改成时间。

C

骨架、单位与实现

单位定义：1 = 直线穿过 1 个区块（chunk，512×512 像素）空隙地形的时间。

四个量构成骨架：

Yz(s)=抽取数z×pz(s)
kz=‖缺口s/Yz(s)‖3
S=∑zkz×单轮耗时z+hops×113.2
  • Yz(s)：在刷点 z 走一轮，期望拿到法术 s 的份数。定义域为非负实数。
  • kz：该刷点要几轮。由三范数 ‖x‖3=(|x1|3+⋯+|xn|3)1/3 聚合，值域非负。
  • hops：跨平行世界次数，取圣山与繁茂轮数的较大者。
  • S：收集难度，单位是时间。

实现位于 src/engine.js：

函数 参数 返回值
Plan.yields(id) 法术 ID 字符串 三个刷点各一轮的期望份数
Score.zoneTimes(ks) 三元素轮数数组 总时间、跨世界次数、轮数和
Score.assignZones(items) {id, lack} 数组 指派、各区轮数与时间、总时间
CFG.setMode(mode) "default" 或 "expert" 生效的模式字符串

四个方案的参数

四个方案共用骨架，差别只在常数与库存规则。

参数 v7 v7.1 v7.2 现行
圣山一轮 51.2 70.7 76.7 76.7
繁茂一轮 672 685.7 685.7 685.7
地狱一轮 387 387 387 387
换世界 不建模 不建模 各区分别，第二轮起 共享，第一轮起

三次改动的动因：

  1. v7 的搜索系数 0.4 / 0.7 / 1.0 没有可测来源。v7.1 换成用户给的物理量：搜 1 区块法杖约等于跑 4 区块，法术约等于跑 2 区块。
  2. v7.1 仍假设商店无限，结果永远偏向圣山。v7.2 补上按轮计价与跨世界成本。
  3. v7.2 让第一轮免费跨世界，等于给圣山打 2.5 折。现行版改为第一轮就付，且圣山与繁茂共享一次跳世界。
E

标度偏差

v7 与 v7.1 的柱子整体在 2~4 之间，说明口径低估了难度。低估源于「不建模库存」：模型以为圣山可以无限刷。

黑闪页偏离最大，达 3.9 倍。它需要的低阶法术种类多，模型认为一轮圣山就能全包。

v7.2 把最大偏差压到 0.36，现行版压到 0.31。

F

时间分到哪个刷点

前两代把 66%~70% 的时间分给圣山，因为圣山单价最低且不限量。

v7.2 之后圣山降到 26%~33%，地狱升到 44%~53%。

这不是模型变严了，而是它终于承认「圣山刷完就没了」。

G

稳定性与排序

变异系数降到 0.119，说明低估是系统性的，不是随机的。乘一个常数就能修正。

项目没有乘这个常数。理由是这个偏差随配方结构漂移，乘上去只会制造「精确到小数」的假象。

秩相关 0.74 不算高。九个配方里有六个互相差距不超过 10%。这个差距落在模型误差内。

工具的用途是同一页内比较候选方案。同页候选共享需求结构，排序比跨页比较可靠。

局限

局限 量化 处理
三范数近似偏小 中位 1.01 不乘校准系数
跨页排序不稳 ρ = 0.74 只用于同页比较
繁茂密度是下界 实测 72 根/42 区块 用户表示可能数少了
每根法杖 4.5 张是均值 槽位类型未细分 修正类偏高，投射物类偏低
地狱密集区位置随机 无法建模 默认扫走廊，熟练搜 10 区块
未建模玩家存活 死亡成本不计 只算时间

熟练模式的一致性更好：变异系数 0.104，秩相关 0.91。三个刷点的单价接近，模型不再被「某处特别便宜」主导。
